---
name: Vercel API routing
description: Non-obvious route behavior for the dashboard hosted on Vercel.
---

A root-level Vercel function catch-all served `/api/healthz` but did not route nested paths such as `/api/market/overview`; Vercel returned an edge `NOT_FOUND`. A broad SPA rewrite had also served `index.html` for API requests.

**Why:** A successful health check alone does not prove nested API routes are reaching the Express app, and an HTTP 200 may be the SPA fallback rather than JSON.

**How to apply:** Keep the SPA fallback from matching `/api/*`. Define function entries at each API namespace for grouped endpoints, and verify at least one nested production endpoint by checking its content type and payload.

Deeper account routes need a Vercel function adapter at the matching nested path depth. A one-segment account adapter and root catch-all can leave grandchild paths as edge `404`s even when the Express route exists.

**Why:** Paper-trade and reset requests returned Vercel `404` before reaching Express, while the same Express endpoint returned the expected authentication `401` locally. Adding a nested adapter changed both production responses to `401`, confirming route dispatch.

**How to apply:** For each multi-segment account endpoint, add a matching nested adapter that reuses the built Express app. Smoke-test protected endpoints without a session and require a JSON `401` rather than a Vercel `404`; do not create test transactions.

Vercel Hobby permits at most 12 Serverless Functions per deployment. When adding a scheduled endpoint, reuse an existing namespace adapter (for example, a secret-protected route under `/api/market/*`) instead of adding another function file when the route shape allows it.

**Why:** A separate Cron adapter exceeded the Hobby function limit; routing it through the existing market adapter kept the deployment within the free-plan cap.

**How to apply:** Count files under `api/` before a Hobby deployment, preserve exact Cron auth on the Express route, and verify the public URL returns `401` without its bearer secret rather than an edge `404`.

Vercel Cron invocations do not follow redirects. When scheduled requests have no function logs, check whether Deployment Protection is redirecting the cron host before changing route logic; preserve SSO and use a supported automation access mechanism.

**Why:** A protected deployment URL returned a Vercel Authentication redirect while the scheduled routes had no invocation records.

**How to apply:** Verify the exact host used by the Cron definition can reach the function without weakening human-facing protection, then confirm the route's own authorization and completion logs.

Deep stock API paths can still return Vercel edge `404`s even when a namespace catch-all exists. Under the Hobby 12-function limit, route known deep paths through an existing shallow stock function with exact rewrites, then restore only allowlisted paths before passing the request to Express.

**Why:** Production AI-scan progress and job endpoints were unreachable before Express, while adding dedicated function files exceeded the Hobby limit.

**How to apply:** Keep the function count at or below 12, rewrite each required deep route to a one-segment stock endpoint, validate the internal route marker against an allowlist, and smoke-test the live endpoint for its expected JSON status instead of relying on `/api/healthz`.

The same edge `404` can affect deeper market endpoints even when a root catch-all and a market namespace function exist. Route the exact client URL through an existing shallow market function and restore it only through an exact allowlist.

**Why:** The ETF market route was present in Express but its deeper URL had no matching Vercel function path; the stable production alias returned edge `404` until the rewrite and allowlisted adapter were added.

**How to apply:** Check the exact URL generated by the frontend, add a constrained rewrite to the market adapter, and verify the production response is the expected JSON payload rather than an edge error.
